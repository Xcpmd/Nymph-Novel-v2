# 2026-09-29

## Anthropic 协议支持 + 批量推理

### 协议抽象
- `ProviderConfig` 新增 `protocol`（openai / anthropic）与 `thinking`（扩展思考开关），
  数据库 `providers` 表补列，走 `ensureColumn` 迁移。
- `lib/ai/client.ts` 重写为协议分派：鉴权头（Authorization+api-key vs x-api-key+anthropic-version）、
  请求体（Anthropic 的 system 提到顶层、max_tokens 必填、temperature 在开启思考时固定为 1）、
  流式解析（delta.content vs content_block_delta / thinking_delta，用量分散在 message_start 与 message_delta）。
- 新增 `normalizeAnthropicMessages` 纯函数：合并连续同类消息、把作为风格前缀的 assistant 并入 system、
  保证首条为 user，6 个单测覆盖。
- `presets.ts` 增加协议、批量能力与「另一套协议入口」，DeepSeek / GLM / MiMo 都提供了 Anthropic 兼容地址，
  设置页可一键切换；新增 Anthropic 原生预设。

### 批量推理
- 新增 `batch_jobs` / `batch_items` 两张表与 `lib/store/batches.ts`；
  `lib/ai/batch.ts` 实现两条路径：供应商原生批量 与 本地并发队列，共用同一套任务模型。
- Anthropic：`POST /v1/messages/batches` 提交，轮询 `processing_status`，从 `results_url` 取 JSONL。
- OpenAI：上传 JSONL 到 `/files` → 建 `/batches` → 完成后拉 `/files/{id}/content`。
- 调度由客户端轮询 `/api/batches` 触发（`advanceBatches`，带 8 秒节流），不依赖常驻进程。
- 供应商批量能力由 `resolveBatchSupport` 决定：显式声明优先，否则按预设与协议推断——
  自定义网关也能声明自己支持 `/batches`。
- 新增 `/novels/[id]/batch` 页面（侧栏「批量」）：选章、模式/并发/思考开关、进度条、
  逐条状态、失败重试、取消、删除；任务落库所以刷新不丢。

### 踩坑
- 改完数据库结构必须重启进程，`migrate()` 每进程只跑一次，热重载不会补列/补表。
- 中途遇到过一批「字段没写进 SQL」的问题：用脚本做多行字符串替换时反引号被 bash 吃掉，
  静默替换失败。**含反引号的多行替换一律用编辑工具，不要走 shell 脚本。**
- 冒烟脚本的自动清理会被沙箱的批量删除保护拦下，会在 `novel/` 留下孤儿目录，需要人工核对后清掉。
