## 三项增量需求

1. **上一章全文可选注入**：新增基础规则槽位 `previous-chapter`（默认不勾选，避免上下文膨胀），
   配套新标签 `{{previous_full}}`。同时修掉一个既有的真实缺陷——基础规则此前无视勾选状态一律发送；
   现在 `assembleContext` 完全按绑定走，基础与独立规则在同一分组内按 sortOrder 交错拼接，
   `{{regulars}}` 只在「使用它的那个分组」展开，且模板里出现过就不再重复追加。
2. **章节手动排序**：`reorderChapters` 全局重编号 1..N 并搬迁正文文件、章节行、标签、书签、检索索引与对应大纲行；
   标签与书签的 ref 改写走 `tmp-` 前缀两阶段，避免目标 ref 被占用。排序语义抽成纯函数
   `src/lib/chapters/order.ts`（moveInOrder / nudgeInOrder / isSameOrder / renumberTitle）。
   标题里的「第N章」前缀会重编号，用户自起的章节名保留。大纲行的冲突让位策略是顺延到末尾，不丢内容。
3. **大纲拆分为章节**：解析逻辑抽成纯模块 `src/lib/outline/parse.ts`，前后端共用；
   大纲页新增拆分预览，逐行勾选、标注「已有章节 / 将新建」，只拆分选中行，拆前自动保存编辑框内容。

- 新增 `scripts/smoke.mjs`（`npm run smoke`）：在运行中的服务上建临时小说跑通三项功能后自动清理，
  15 项断言全绿。单测从 55 增至 86。
